`sessionTitle` (renames the session, same effect as `/rename`) is a valid `hookSpecificOutput` field on **only two** hook events: `SessionStart` and `UserPromptSubmit` — confirmed against the installed `@anthropic-ai/claude-agent-sdk` (`node_modules/@anthropic-ai/claude-agent-sdk/sdk.d.ts`: `SessionStartHookSpecificOutput`, `UserPromptSubmitHookSpecificOutput`) and this repo's own compile-time proof in [lib/validate/hook-schema-sdk-typecheck.mjs](../../lib/validate/hook-schema-sdk-typecheck.mjs) (`USER_PROMPT_SUBMIT_SHAPE` includes `sessionTitle: ""`, type-checked against the real SDK). `WorktreeCreate` (`hookSpecificOutput` is only `{hookEventName, worktreePath}`, `worktreePath` required) and `CwdChanged` (only `{hookEventName, watchPaths?}`) do NOT support it. `WorktreeCreate` is a *creation-strategy override* hook — it replaces `git worktree add` itself (command hooks must print the bare path to stdout, no JSON) — not an "after entering" notification hook.

**Why:** the official docs page (code.claude.com/docs/en/hooks), when read through `WebFetch`, under-reports this — its summarizer surfaced `sessionTitle` only under `SessionStart` and explicitly claimed it's "exclusive to SessionStart, cannot be set by WorktreeCreate, CwdChanged, or any other hook event." That last clause is wrong: it missed `UserPromptSubmit`, which the real SDK type, this repo's own [tests/hook-schema.test.mjs](../../tests/hook-schema.test.mjs) (search `sessionTitle`, ~L559-570, explicit positive/negative cases for `UserPromptSubmit`), and [lib/validate/hook-schema-core.mjs](../../lib/validate/hook-schema-core.mjs) (`checkHookSpecificOutput(hso, "UserPromptSubmit", ["additionalContext", "sessionTitle"])`) all confirm as valid. When a `WebFetch` summary of Anthropic's own docs disagrees with the installed SDK `.d.ts` or this repo's own passing tests/typecheck, trust the `.d.ts`/tests — `WebFetch` runs the page through a small summarizing model and can silently drop table rows.

**How to apply:** to auto-name a session after the worktree it's running in, two separate entry points need separate fixes, because they fire through different hook events:
1. Session *boots* already inside a worktree (`--worktree` flag, `--worktree "#1234"` PR checkout, desktop app's automatic per-session worktree) → `SessionStart` fires once with `source: "startup"|"resume"`. Extend [templates/hooks/worktree-session-ctx.mjs](../../templates/hooks/worktree-session-ctx.mjs) to also emit `sessionTitle`.
2. Worktree entered **mid-session** (user says "work in a worktree" → the `EnterWorktree` tool runs) → the session does **not** restart, so `SessionStart` never refires. Only `UserPromptSubmit` (fires on every prompt) can catch this transition. Extend [templates/hooks/worktree-prompt-ctx.mjs](../../templates/hooks/worktree-prompt-ctx.mjs) instead.

Both events already receive the *current* title on input (`SessionStartHookInput.session_title` / `UserPromptSubmitHookInput.session_title`, snake_case) — check it before overwriting so a manual `/rename` never gets clobbered (`UserPromptSubmit` fires on *every* prompt, so without this check the hook would stomp the title every single turn). The worktree name is simply `path.basename()` of the `.claude/worktrees/<name>` match both hooks already compute via their existing regex — no new detection logic needed, just add the field to the JSON they already emit.

## Dead ends — don't retry these (confirmed, not just "untested")

Renaming synchronously **at the moment `EnterWorktree` runs** (i.e. from a `PreToolUse`/`PostToolUse` hook matched on `EnterWorktree`, instead of waiting for the next `UserPromptSubmit`) is **not possible today**, confirmed three independent ways:

1. **No agent-callable rename tool exists.** Full SDK tool-name union in `sdk-tools.d.ts` has zero hits for `Rename`/`SetTitle`/`SessionTitle`. Matches open upstream request [anthropics/claude-code#50040](https://github.com/anthropics/claude-code/issues/50040) ("Allow assistant to programmatically rename sessions via tool call") — closed only as a duplicate of #33181, i.e. still unresolved, not shipped.
2. **`PostToolUse`/`PreToolUse` `hookSpecificOutput` has no session-title field, by design, not omission.** `PostToolUseHookSpecificOutput` = `{hookEventName, additionalContext?, updatedToolOutput?, updatedMCPToolOutput?}` only — confirmed in the real `.d.ts`, in this repo's own CLAUDE.md hook table, AND in Anthropic's own SDK hooks doc prose (`code.claude.com/docs/en/agent-sdk/hooks`), which explicitly enumerates PostToolUse's complete output surface as exactly those three fields.
3. **Writing the session's JSONL directly (what `renameSession()` does under the hood, and what a hook could do by hand) does NOT update the live/visible session title.** A community member on [anthropics/claude-code#44786](https://github.com/anthropics/claude-code/issues/44786) tested this precisely: wrote `{"type":"custom-title",...}` lines into the session JSONL (both appended at EOF and replacing the existing entry) — "no sidebar update, even after desktop-app relaunch." So the on-disk JSONL is **not authoritative** for what the UI displays; there's a separate stat-log/index the sidebar actually reads, which nothing in the public API can write to. Corroborated by two more open bugs on the same root cause: #37449 (stat-log index not synced from JSONL) and #39228 (sessions with a mid-file `custom-title` vanish from the panel). Do not attempt calling the SDK's `renameSession(sessionId, title, options)` from a hook expecting it to live-update the title — same mechanism, same confirmed failure.

**Conclusion:** the one-prompt-later `UserPromptSubmit`/`sessionTitle` approach above is not a workaround for a missing direct path — it is the *only* path that actually works, because the "instant, at-the-tool-call" version requires platform support (a `SessionRename` hook event, or hook-writable stat-log access, or an agent-callable rename tool) that multiple open GitHub issues are still requesting as of 2026-04.
